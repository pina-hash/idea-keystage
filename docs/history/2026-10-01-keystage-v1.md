The repository held one README line (`9bee0b1`). This bundle built the whole app: version 0.1.0 of IDEA Keystage, for Mr. Pina to record SolidWorks tutorials for the IDEA engineering pathway.

## Why it is built the way it is

Tutorial viewers need to see which shortcut was pressed and what it does, and a teacher needs that without ever showing a password or a private message on a recording. So every decision about what is shown is made once, in one pure Rust crate (`keystage-core`), and the renderer only draws. Privacy is enforced at every layer: the hooks only copy a record; keys are held from each focus change until Windows says the new field is not a password; anything uncertain is hidden; nothing typed reaches disk unless the user started a Session Log; the app makes no network request at all.

SolidWorks captions are the second rule. Dassault publishes no complete list of default shortcuts, and many shortcuts people "know" are undocumented. Every caption therefore comes from the 2025 and 2026 help, with the page, version, date and a verbatim quote, and the gaps are listed instead of filled. The Copy List import lets Mr. Pina bring his own complete list.

## What was built

- **Phase 1 research** (`docs/DECISIONS.md` items 1 to 8): the stack (Tauri 2.12.1, Rust, Svelte 5), the SolidWorks data (364 keyboard and 183 mouse entries from 294 help pages, 31 differences between 2025 and 2026, 17 gaps), the import routes, OBS Browser Source and obs-websocket 5, password and foreground detection, low-level hook limits, and cross-checking Windows code from Linux. Keystro parity is in `docs/PARITY.md`.
- **Input core**: event model, processor (combos, repeats, chords, text runs, masking, mouse drags, double clicks, wheel and gestures, AltGr), profiles and caption matching, Copy List and `.sldreg` importers, settings, the wire protocol, and 12 synthesized sound packs.
- **Windows layer**: hook thread with a watchdog and stall probe, foreground watcher, UI Automation password check with the hold word, legends from the active layout, monitors, the overlay style guard, DPAPI.
- **Renderer and visuals**: one Svelte overlay for Host A, OBS and the settings preview; six themes plus a custom theme; six keyboard layouts with live legends and ISO detection; a mouse diagram; cursor ring, spotlight or dot with ripples, trail and wheel chevrons. Built to Chromium 103 for OBS 30.
- **App shell and settings window**: pipeline, Host A, tray, global hotkeys, 31 IPC commands with per-command permissions, settings store, sessions, sound, first-run setup and twelve settings pages with a live preview.
- **Server, OBS and sessions**: a `127.0.0.1:47820` server with Host and Origin checks, an obs-websocket client with recording timecodes and chapters, Session Logs with SRT, Markdown, JSON and YouTube chapter exports (`docs/SESSION_FORMAT.md`).
- **CI and release**: Linux and Windows CI jobs (CI run 14 green, including 202 app and platform tests on `windows-latest` with a real injected key through the hook), a tag-triggered release that runs CI first and publishes the installer, the portable exe and checksums; screenshot and latency harnesses.
- **Reviews**: three rounds with adversarial verifiers; every confirmed finding fixed except one display-only Caps Lock case (`docs/DECISIONS.md`, Build decisions).

## What was measured

All on the Linux build container (details and instruments in `docs/DECISIONS.md`, Performance): the core handles an event in 75 ns (general profile) or 157 ns (SolidWorks profile); a burst of 20 keys per second for 10 s lost nothing in the core, the renderer, or end to end through the real server into headless Chromium (200 sent, 200 rendered); server send to the first animation frame after the DOM change had a median of 6.6 ms in the latest run (9.5 to 10.6 ms in earlier runs) and to the next frame 23 to 27 ms; an idle overlay page used about 0.1 percent of one core and drew no frames.

## What was left undone

- Nothing was run on Windows outside CI, in OBS, or with SolidWorks. Host A behavior over SolidWorks, password detection in real browsers, OBS loading loopback URLs, the installer and SmartScreen, and Windows performance are unverified. The checklist below covers the essentials.
- The SolidWorks importers are unvalidated until real Copy List and `.sldreg` exports exist.
- Not built: code signing, an updater, website integration (designs only), a cursor hide timer, macOS. See `docs/ROADMAP.md`.

## First run on Windows

Mr. Pina does this once, after the release is published.

1. Download `IDEA-Keystage_0.1.0_x64-setup.exe` from https://github.com/pina-hash/idea-keystage/releases/latest and run it. If Windows says "Windows protected your PC", click **More info**, then **Run anyway**. Start IDEA Keystage from the Start menu.
2. In the first-run setup, pick the monitor you record, keep the IDEA look, choose **Both** for output, and press **Finish**. The IDEA Keystage icon appears in the tray.
3. Open SolidWorks and a part. Click once in the graphics area, then press `F`. Expect a callout near the bottom center showing `F` with the caption **Zooms to fit**, and the model zooming to fit (SolidWorks keeps the focus). Then middle-drag in the graphics area: expect `Middle drag` with **Rotate View** and "Parts and assemblies only" in small type. Alt+Tab should not list the overlay.
4. Open Edge, go to any sign-in page, click its password field and type a few letters. Expect no letters and no keys on screen, and a small "Hidden" pill that says "Password field".
5. In OBS: Sources, +, Browser. Set URL `http://127.0.0.1:47820/overlay/keys`, Width `884`, Height `632`. Leave Local file, Use custom frame rate and Control audio via OBS off, leave Custom CSS at its default, and leave **Shutdown source when not visible** and **Refresh browser when scene becomes active** off. Press `F` in SolidWorks again: the callout appears in the OBS preview, and the on-screen overlay steps aside while OBS shows the source (that is what **Both** means).
6. Press `Ctrl+Alt+Shift+P`. Type in SolidWorks: nothing shows, and the tray says Paused. Press it again to resume.
7. If any step differs, tell Claude: the step number, what you expected and what you saw, a screenshot, your Windows version (run `winver`), and your OBS and SolidWorks versions. Also copy any notices on the settings Home page. The log at `%LOCALAPPDATA%\com.ideabosco.keystage\logs\keystage.log` holds no keys or text and can be attached.
